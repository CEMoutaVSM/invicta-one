# L2 — Visma Org Standards (Story Writing)

Scope: all Visma Tech Portugal projects. Owner: Engineering Practice. Review: quarterly.
Change here affects every project. Project-specific rules belong in L3.

| ID | Rule |
|---|---|
| L2-STORY-01 | A story states an actor, an action and an outcome. Missing any one → BLOCKED. |
| L2-STORY-02 | Acceptance criteria use Given-When-Then. No prose criteria. |
| L2-STORY-03 | Each criterion is independently testable by someone absent from refinement. |
| L2-STORY-04 | Non-functional expectations (performance, accessibility, i18n) are stated or explicitly deferred, never silent. |
| L2-STORY-05 | Stories never carry estimates, points or assignees. Those are planning artefacts. |
| L2-SEC-01 | Any story touching personal data names the lawful basis and the retention period, or asks for it. |
| L2-SEC-02 | Stories involving authentication or authorisation state the failure behaviour, not only the happy path. |
| L2-A11Y-01 | User-facing UI stories include at least one keyboard or screen-reader criterion. |

## Definition of Ready
READY requires: zero MISSING markers, zero unanswered blocking questions,
at least one negative-path acceptance criterion, and scope explicitly bounded.
