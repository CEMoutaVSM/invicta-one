# L2 — Visma Org Standards (Release Notes)

Scope: all Visma Tech Portugal products. Owner: Product Practice. Review: quarterly.

| ID | Rule |
|---|---|
| L2-REL-01 | Customer-facing sections contain no hashes, branch names, ticket keys or internal component names. |
| L2-REL-02 | Every entry is written from the customer's point of view, in the second person or impersonal. |
| L2-REL-03 | Grouping is New / Improved / Fixed. Never grouped by team, component or commit type. |
| L2-REL-04 | Security fixes are disclosed as "security improvements" without exploit detail, and never omitted. |
| L2-REL-05 | Breaking changes appear first, under an explicit heading, with the required customer action. |
| L2-REL-06 | No marketing superlatives: no "revolutionary", "game-changing", "seamless". |
| L2-REL-07 | An empty release is stated plainly. Padding a release is a defect. |

## Tone
Plain, factual, short. One sentence per entry where possible.
Write for an accountant who is busy, not for an engineer who is curious.
